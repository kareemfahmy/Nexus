# Nexus: project memory

Portfolio-grade Angular + Supabase facility and IoT operations platform. It's inspired by Facility Smart Grid (FSG) but redesigned from scratch.
The full approved plan is in `docs/architecture-plan.md`. Read it before starting any milestone.

## Approved decisions (Milestone 1)
- Angular 22 (latest stable), standalone, zoneless, OnPush (the v22 default, so don't set it explicitly), strict TS, selector prefix `nx`, SCSS, CSR only (no SSR).
- Forms: **Reactive Forms** (typed, `nonNullable`). This deliberately overrides the Signal Forms preference in the Angular rules below.
- UI layer: **custom SCSS design tokens** (primitive → semantic → component) + `@angular/cdk` + `@angular/aria`. No Tailwind, no Material or PrimeNG.
- Theme: **light only**. Tokens are layered so dark mode can be added later.
- Fonts: IBM Plex Sans (UI) + IBM Plex Mono (IDs and numbers). This overrides ui-ux-pro-max's Fira suggestion.
- Libraries: `@supabase/supabase-js`, `echarts` + `ngx-echarts`, `@lucide/angular` (NOT `lucide-angular`, which doesn't support v22; register icons in `shared/ui/icon.ts`), `date-fns`. There's one library per job, so don't add duplicates.
- Services: use the v22 `@Service()` decorator (`@Service({ autoProvided: false })` for route-scoped stores).
- Data access: Supabase queries live ONLY in `features/*/data/*.service.ts`. Components and stores use `resource()`. Per-feature signal stores are used, with no NgRx.
- List state (sort, filter, page) lives in URL query params.
- Demo access: guest "Explore demo" button uses Supabase anonymous sign-in, which gives the viewer role (read-only). Real accounts get the operator or admin role.
- Security is RLS on every table, via `public.auth_role()`. UI guards only improve UX and aren't the enforcement layer.
- Styling rule: components use semantic tokens (`var(--…)`) only, never raw hex. Check with `node .claude/skills/design-system/scripts/validate-tokens.cjs --dir src/`.

## Supabase
- The cloud sandbox network policy blocks *.supabase.co, so browser sign-in can't be tested from the container (MCP tools still work). The user tests auth in their own browser.
- Hosted project "Nexus": ref `csblzgxsskyfpgsevlgd`, eu-central-1, Postgres 17.
- Migrations in `supabase/migrations/` are the source of truth. They're applied via the Supabase MCP `apply_migration` (6 applied: 0001-0006).
- Dry-run new SQL on a local Postgres 16 first (`/usr/lib/postgresql/16/bin`, run as the `postgres` user) with an `auth` schema stub, then apply to the hosted project.
- After schema changes, run `supabase/tests/rls_and_rules.test.sql` (expected: `RLS_TESTS_PASSED`) and `get_advisors`. The accepted findings are listed in docs/rls.md.
- People model: assignees and authors reference `team_members` (not auth users). Real users get a linked team_members row on signup. Roles live in `profiles.role` and are promoted only via SQL.
- Seed: `supabase/seed.sql` is deterministic (md5-hash helpers keyed on stable natural keys, never UUIDs) and time-relative.
- Regenerate `src/app/core/supabase/database.types.ts` after every migration.
- Only the publishable key goes in frontend env files. Never put the service-role key there.

# Angular coding rules (generated by Angular CLI `--ai-config=claude-code`)

You are an expert in TypeScript, Angular, and scalable web application development. You write functional, maintainable, performant, and accessible code following Angular and TypeScript best practices.

## TypeScript Best Practices

- Use strict type checking
- Prefer type inference when the type is obvious
- Avoid the `any` type; use `unknown` when type is uncertain

## Angular Best Practices

- Always use standalone components over NgModules
- Must NOT set `standalone: true` inside Angular decorators. It's the default in Angular v20+.
- Do NOT set `changeDetection: ChangeDetectionStrategy.OnPush` explicitly. `OnPush` is the default in Angular v22+.
- Use signals for state management
- Implement lazy loading for feature routes
- Do NOT use the `@HostBinding` and `@HostListener` decorators. Put host bindings inside the `host` object of the `@Component` or `@Directive` decorator instead
- Use `NgOptimizedImage` for all static images.
  - `NgOptimizedImage` does not work for inline base64 images.

## Accessibility Requirements

- It MUST pass all AXE checks.
- It MUST follow all WCAG AA minimums, including focus management, color contrast, and ARIA attributes.

## Components

- Keep components small and focused on a single responsibility
- Use `input()` and `output()` functions instead of decorators
- Use `model()` for two-way bound properties with `[(prop)]` syntax instead of pairing `input()` with `output()`
- Use `computed()` for derived state
- Use `linkedSignal()` for state derived from multiple reactive sources that must stay synchronized
- Prefer inline templates for small components
- Forms: **Nexus uses typed Reactive Forms** (project decision, see above). The CLI default would be Signal Forms.
- Do NOT use `ngClass`, use `class` bindings instead
- Do NOT use `ngStyle`, use `style` bindings instead
- Do NOT import `CommonModule`, import only the directives and pipes the template uses, such as `AsyncPipe` or `DatePipe`
- When using external templates/styles, use paths relative to the component TS file.

## State Management

- Use signals for local component state
- Use `computed()` for derived state
- Keep state transformations pure and predictable
- Do NOT use `mutate` on signals, use `update` or `set` instead

## Templates

- Keep templates simple and avoid complex logic
- Use native control flow (`@if`, `@for`, `@switch`) instead of `*ngIf`, `*ngFor`, `*ngSwitch`
- Use the async pipe to handle observables
- Do not assume globals like (`new Date()`) are available.

## Services

- Design services around a single responsibility
- Use the `providedIn: 'root'` option for singleton services
- Prefer the `@Service` decorator over `@Injectable({providedIn: 'root'})` for new singleton services (Angular v22+)
- Use the `inject()` function instead of constructor injection
